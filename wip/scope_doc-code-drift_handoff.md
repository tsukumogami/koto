## Problem Statement

koto v0.12.0 shipped a binary that tells users to run `koto session rebind`, a
subcommand that does not exist, and every gate the work ran stayed green — `cargo
fmt --check`, `cargo clippy --all-targets`, the full test suite, and CI on all
fifteen issues of the plan. Nothing in the repo asserts that a name appearing in
an error message, a guide, or a shipped skill resolves to anything real. It is a
class rather than an incident: the same silence covers a shipped plugin telling
an agent to run `koto query`, a const handed to every respawning agent naming
`koto session info`, seven dead repo-relative paths in user-facing guides, and a
`CLAUDE.md` structure block citing two directories that do not exist. The
decidable core of the class — a name that should resolve, resolving — is
mechanically checkable against ground truth the compiler already holds.

## Scope Boundary

### In scope

- **Verb resolution.** Every `koto <verb> [<subverb>]` token inside a backtick
  span or a ```bash/```sh fence, resolved against the live clap command tree
  walked from `koto::cli::App::command()`.
- **Path resolution.** Every backticked repo-relative path whose first segment
  names a real top-level directory, resolved by filesystem stat, with any
  trailing `:line` or `:start-end` suffix stripped first.
- **`src/**/*.rs` as a first-class surface**, not an afterthought: string
  literals and `///` doc comments both reach users, and the motivating defect
  lives in three string literals.
- **`plugins/koto-skills/**`**, the surface agents actually execute.
- **Load-bearing markdown**: `docs/guides/`, `docs/reference/`, `docs/testing/`,
  `docs/STABILITY.md`, `docs/workspace-layout.md`, `README.md`, `CLAUDE.md`.
- **An escape hatch** with a mandatory issue reference that fails on stale
  entries as well as new findings.
- **Fixing the findings the check produces**, or allowlisting each against a
  filed issue — the check has to land green.
- **Auditing `validate-plugins.yml`'s template-compilation glob**, which matches
  two files and compiles one while the four shipped example templates sit
  outside it.

### Out of scope

- **Code identifiers.** 70% of backticked spans, and 17–23% of them legitimately
  do not appear in `src/` (example state names, illustrative env vars, Windows
  API names). Ten times the false-positive rate of verbs. This is the check that
  gets disabled in a week.
- **Record surfaces** — `docs/designs/`, `docs/prds/`, `docs/briefs/`,
  `CHANGELOG.md`. They hold 120 of the corpus's 129 unresolved verbs, and a
  design doc weighing `koto record` against `koto annotate` before choosing
  `koto decisions record` is doing its job. `docs/designs/archive/` alone runs a
  31% miss rate, by design.
- **Prose accuracy.** Not decidable. Every instance in the corpus is a *naming*
  failure; that is the honest boundary of cheap.
- **Flags.** `get_arguments()` makes them equally decidable and they would catch
  the `--parent` half of the respawn-prompt bug, but the noise is unmeasured and
  verbs alone catch both known incidents.
- **Instance 3's `CLAUDE.local.md`.** Untracked in koto, generated by niwa from
  `dot-niwa`. No check in koto's CI can see the file. The same rot in the
  *tracked* `CLAUDE.md` is in scope.
- **Instance 4 (shirabe's `CLAUDE.md`).** Different repo, no koto crate to walk.
- **Instance 2's runtime half.** "Compiles, then cycle-detects on the second
  poll" is not statically decidable. The compile half is in scope via the glob
  audit.
- **Doctests for the 105 ```rust fences.** A real adjacent slice of the same
  class; file separately if wanted.

## Decisions Already Settled

- The checkable claim is "a name that should resolve, resolves" — verbs and
  paths, nothing else.
- `src/**/*.rs` is the primary surface, because the docs were right and the
  binary was wrong. All six load-bearing mentions of `koto session rebind` at
  v0.12.0 explicitly say the subcommand does not exist; the three Rust string
  literals are the liars. A markdown-only check finds nothing at the site of the
  incident.
- Requiring a backtick is the whole trick for `src/`: 42 raw unresolved mentions
  collapse to 10, all genuine, because `koto writes` / `koto builds` /
  `koto renders` prose never sits in code font.
- Ground truth is walked from `koto::cli::App::command()`, never hardcoded and
  never scraped from `--help`. This makes every finding self-retiring: when
  koto#215 lands `koto session rebind`, the finding disappears without anyone
  editing the check.
- It ships as a Rust integration test rather than a `scripts/check-*.sh`. This
  overrides the house's shell-checker style deliberately, and the reason is
  ground truth: a script reaches the verb set only by building the binary (koto
  pulls ratatui, rust-s3, crossterm) or by hardcoding it, and hardcoding
  reintroduces the drift being checked. `tests/lib_reexports.rs` is koto's own
  precedent for an in-tree check that a surface has not moved. The house
  *conventions* carry over regardless of language.
- It must run on `src/**` changes. `validate.yml` runs `cargo test` with no
  `paths:` filter; every existing content check is gated on `plugins/**` or
  `docs/**`, which is the specific topology that let v0.12.0 ship green.
- The escape hatch is a tab-separated allowlist with a mandatory `owner/repo#N`,
  failing in both directions. Adopted from shirabe's
  `check-template-directives.allow`, whose header states why a lint needs one:
  a lint that cannot land until the defects it finds are fixed does not land.
  Bidirectional staleness is what stops it becoming a permanent suppression list.
- koto only, not koto and shirabe.

## Coverage Notes

- **The allowlist's exact record shape is not settled.** shirabe's five-field
  form (rule, subject, file, issue, reason) is the model, but the field set for
  verb-vs-path findings, and whether a record is scoped to one file or matches
  repo-wide, is a design question.
- **The disposition of each live finding is not settled.** `koto session rebind`
  must be allowlisted against koto#215 rather than fixed, because a concurrent
  session owns the verb and fixing the messages would conflict. But
  `koto session info` in `RESUME_CONTEXT_PROMPT` is guarded by a byte-equality
  snapshot at `tests/respawn.rs:597`, so fixing it means touching that test —
  fix-versus-allowlist per finding needs deciding.
- **Whether the path check and the verb check are one test or two** is open. They
  share an extractor and a surface list but nothing else.
- **How the surface list is expressed** — an explicit path list in the test, or a
  rule derived from the existing `status:` frontmatter and `docs/designs/archive/`
  layout — is unsettled. The frontmatter route is self-maintaining; the explicit
  list is legible. Note that `docs/guides/` and `docs/reference/` carry no
  frontmatter at all, so the frontmatter route needs a default.
- **The failure message format** matters more than usual here: the check will
  fire on a contributor who did nothing wrong except rename a verb, and the
  message has to say which token, in which file, and what to do about it.
- **Not measured:** whether the check's runtime is material. The clap walk is
  0.00s; the corpus scan reads ~2.5 MB of markdown plus 78k lines of Rust. Almost
  certainly fine, unmeasured.

## Upstream Observations

The exploration read `docs/designs/current/DESIGN-koto-runs-commands.md`, which
specifies `koto session rebind <name> [--to <dir>]` at line 691 and is
`status: Current`. That document is where the phantom verb was designed; it is
context for koto#215 rather than upstream for this work, and it is not being
passed as `--upstream`.

It also read `docs/guides/default-action-authoring.md`,
`docs/reference/error-codes.md`, and the three `koto-skills` SKILL.md files, all
of which correctly document the verb as unimplemented. Worth noting for whoever
writes the check: three of the four documents that enumerate `koto session`'s
subcommands are stale in three different ways (one omits `recover` and `update`,
two omit `recover`), and the correct one is
`plugins/koto-skills/skills/koto-user/references/command-reference.md:698`. The
prose written to explain the first drift instance has itself drifted.

No ROADMAP exists for this topic. Nothing is passed on `--upstream`.

## Framing-Shift Answer

**Pre-supplied answer:** yes, the framing shifted.

**Evidence:** the dispatch framed this as documentation naming things the code
does not provide — drift flowing docs-outward. Round 1 established the opposite
direction at the site of the motivating incident. Three independent leads
(v0120-forensics, prior-art, surface-inventory) each found that all six
load-bearing documentation mentions of `koto session rebind` at v0.12.0
explicitly tell the reader the subcommand does not exist, one of them under a
section heading reading `## koto session rebind — not implemented`. The binary's
three string literals are the stale surface. This moves the scope boundary: a
doc-only check — which is what "documentation names something the code does not
provide" implies, and what every ecosystem option (trycmd, generated CLI
references, lychee, doctests) is built for — would have found nothing at the
site of the defect.

A second shift: the anticipated failure mode was a check firing on prose. A
40-span random sample drew zero prose-in-backticks, and the real risk turned out
to be code identifiers at 70% of the population.

## Shape Signals

### Architectural alternatives left open

- **One test or two.** A single `tests/doc_code_drift.rs` covering verbs and
  paths shares the extractor and the surface list; two tests give independent
  failure messages and let one land before the other. Cost of one: a longer file
  and a coupled allowlist. Cost of two: a duplicated corpus walk.
- **Surface list as literal paths versus derived from frontmatter.** The literal
  list is legible and reviewable in the diff; it needs editing when a directory
  is added. The derived rule (skip `status: Superseded`, skip
  `docs/designs/archive/`, skip anything carrying `schema: design/v1` or
  `prd/v1`) is self-maintaining but needs a default for `docs/guides/` and
  `docs/reference/`, which carry no frontmatter at all.
- **Allowlist granularity.** A record keyed on the token alone (`koto session
  rebind` anywhere) is short and retires cleanly; a record keyed on token plus
  file is precise but needs six entries for the rebind cluster and rots when a
  file moves.
- **Whether the `validate-plugins.yml` glob widening rides in the same PR** or
  is filed separately. It is a one-line change that would have caught instance 2,
  and it is a different mechanism from the check.

### Complexity signals

- The exploration made eight architectural decisions, one of which (test over
  shell script) deliberately overrides a documented house convention and needs
  its reasoning on record.
- The check cannot land red, and it currently has findings in at least six
  distinct places, at least one of which is guarded by a byte-equality snapshot
  test that makes the obvious fix a test change. Landing is a real sequencing
  problem, not a formality.
- The acceptance bar is specific and externally set: the check must be
  demonstrated firing on the three `koto session rebind` literals as the tree
  stood at `v0.12.0`. `src/cli/mod.rs` is byte-identical between `v0.12.0` and
  `origin/main`, so this is provable on HEAD — but it must be demonstrated
  rather than assumed, which means a fixture-based test case, not just a green
  run.
- A concurrent session is implementing `koto session rebind` under koto#215. The
  work must not depend on whether that has merged, and the clap-walked ground
  truth is what makes that true.
